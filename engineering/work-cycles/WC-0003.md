WC-0003 is **planning-complete**. The cycle established the normative downstream compiler path from a validated immutable Monad Semantic Graph (MSG), through a validated immutable Kernel Intermediate Representation (KIR), into governed backend candidate output, independent validation, atomic publication, and bounded bootstrap and self-hosting evidence.

## 1. Purpose

WC-0003 defines how Monad converts canonical semantic knowledge into target-specific artifacts without transferring semantic authority to derived representations, backends, caches, generated files, or self-hosting results.

The governing one-way flow is:

```text
validated immutable MSG
  -> validated immutable KIR
  -> isolated backend candidate output
  -> independently validated artifact set
  -> atomic publication
  -> bounded comparison evidence
```

MSG remains the canonical semantic authority. KIR is a derived operational projection. Backend output is an untrusted candidate. Publication is a separate governed transaction. Self-hosting is evidence with declared limits and trust assumptions, never circular proof of correctness.

## 2. Scope

### 2.1 In scope

WC-0003 covers:

- immutable, versioned, validated KIR and canonical encoding;
- domain-separated KIR identities, fingerprints, lineage, and provenance;
- deterministic, target-specific MSG-to-KIR lowering;
- explicit preservation, deferral, approximation, omission, unsupported, and blocked dispositions;
- partial KIR readiness, prohibited backends, missing guarantees, and blocking scope;
- immutable target profiles and backend descriptors;
- deterministic backend discovery, selection, and capability negotiation;
- least-authority backend execution and explicit effect declarations;
- backend-specific dependency observation, invalidation, planning, and verified reuse;
- independent candidate validation and source-map traceability;
- path, collision, permission, policy, syntax, semantics, provenance, secret, and completeness checks;
- user-authored content protection and precondition digests;
- atomic artifact-set publication, interruption recovery, and rollback;
- bootstrap compiler stages and provenance;
- bounded semantic, KIR, artifact, byte, behavioral, and diverse compilation comparisons;
- reproducible first-divergence analysis; and
- differential, property, mutation, fault, security, publication, and false-claim conformance evidence.

### 2.2 Out of scope

WC-0003 does not implement or approve:

- source discovery, parsing, name resolution, or canonical semantic construction owned upstream;
- MSG graph identity, canonical graph serialization, validation, immutability, or readiness owned by MSC-CORE-0008;
- compiler-wide diagnostic envelopes, normalized requests, manifests, dependency tracking, caching, deterministic execution, or reproducibility vocabulary owned by MSC-CORE-0009;
- use of KIR, caches, artifacts, or backend state as canonical semantic knowledge;
- backend mutation of MSG or KIR;
- direct backend publication authority;
- unrestricted filesystem, network, environment, subprocess, clock, randomness, or secret access;
- self-reproduction as proof of correctness;
- completion of PI-002 or M-002; or
- activation or completion of any implementation packet.

## 3. Governing invariants

1. Semantic authority flows one way from validated MSG into derived KIR and never returns from downstream artifacts.
2. KIR is immutable, validated, versioned, canonical, and provenance-bearing before backend consumption.
3. Every applicable semantic construct receives an explicit lowering disposition.
4. Ambiguous lowering cannot be resolved by registration order, filesystem order, traversal order, or scheduling.
5. Target identity and backend identity remain distinct.
6. Unknown, missing, contradictory, or incompatible capability state fails closed.
7. Backends receive least authority and cannot mutate MSG, mutate KIR, or publish directly.
8. Backend success produces an untrusted candidate, not an accepted artifact set.
9. Reuse requires affirmative compatibility evidence and cannot bypass validation or publication policy.
10. Clean compilation remains the correctness oracle for differential comparison.
11. Artifact identity uses canonical logical paths rather than machine-local absolute paths.
12. Publication is atomic at the governed artifact-set boundary and preserves the last accepted set on failure.
13. User-authored content is never overwritten without explicit policy and matching preconditions.
14. Bootstrap provenance and trust assumptions remain visible at every stage.
15. Each self-hosting claim names its comparison level, inputs, environment, cache policy, exclusions, taints, and authority.
16. Equality or reproduction at one comparison level cannot be reported as proof at another.
17. AI may explain or propose but may not alter semantic authority, waive blockers, grant capability, approve publication, promote a compiler, or claim equivalence independently.
18. Architecture remains frozen by default and changes only through constitutional governance.
