# WP-AF-0004 — Establish the Canonical Monad Glossary

## Executive Summary

Create the canonical vocabulary for the Monad ecosystem.

The glossary establishes authoritative definitions for the terminology used throughout specifications, ADRs, work packets, implementation, documentation, engineering journals, and future tooling.

The purpose of this work packet is to eliminate ambiguity by ensuring that every important architectural concept has one accepted definition.

---

# Problem Statement

As engineering systems mature, terminology tends to drift.

Different contributors use the same word to mean different things.

Examples include:

* artifact
* graph
* compilation
* knowledge
* specification
* projection
* authority

When terminology becomes inconsistent, specifications become harder to implement and architectural discussions become less precise.

Monad requires a single canonical glossary that serves as the authoritative reference for the project.

---

# Motivation

The glossary provides a stable semantic foundation for the architecture.

Every future specification should either:

* reference an existing glossary definition, or
* introduce a new term through the glossary.

The glossary becomes the project's engineering dictionary.

---

# Objectives

The work packet will produce a glossary that:

1. Defines canonical engineering terminology.
2. Eliminates ambiguous architectural language.
3. Establishes preferred terminology.
4. Identifies deprecated terminology where applicable.
5. Provides a common vocabulary across all Monad domains.
6. Supports future semantic compilation.

---

# Scope

Included:

* creation of `vision/glossary.md`;
* definition of core architectural terms;
* establishment of canonical terminology;
* cross-references between related concepts.

---

# Out of Scope

Excluded:

* ontology modeling;
* compiler implementation;
* storage implementation;
* serialization formats;
* API definitions.

Those activities belong to later specifications.

The work packet is complete when:

# Architectural Impact

The glossary establishes the semantic vocabulary of the Monad architecture.

It does not introduce new architecture.

Instead, it formalizes existing architectural concepts and provides a stable language for future specifications.

The glossary is expected to become one of the most frequently referenced documents within the Monad repository.
