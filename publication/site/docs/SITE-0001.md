# SITE-0001 of 12 — Documentation Site Architecture and Bootstrap

**Status:** Complete
**Site root:** `publication/site/`
**Framework decision:** Next.js + Fumadocs + Tailwind CSS + TypeScript + Bun

The scaffold uses the current Fumadocs architecture: Fumadocs Core/UI `16.14.0`, Fumadocs MDX `15.2.2`, Next.js `16.3.0`, and React `19.2.8`. Fumadocs currently requires Next.js 16 and Tailwind CSS 4 for its documented Next.js setup, and its MDX integration is ESM-only, which is why the scaffold uses `next.config.mjs`. ([GitHub][1])

One correction to the earlier plan: Fumadocs `16.14.0` replaced Orama internally with **ZBSearch**. The public search module paths remain unchanged, so the site still uses `createFromSource()` from `fumadocs-core/search/server`. ([GitHub][1])

## Architecture established

### 1. Presentation code is isolated

```text
publication/site/
```

owns:

* Rendering
* Routing
* Search
* Site components
* Styling
* Publication metadata
* Derived editions
* Build and deployment behavior

It does not become the canonical owner of Monad’s engineering documents.

### 2. Canonical documents remain domain-oriented

The intended long-term source directories remain:

```text
journal/
architecture/
adrs/
specifications/
engineering/
research/
knowledge/
build-log/
```

The files currently under:

```text
publication/site/content/system/
```

are explicitly marked as bootstrap fixtures. They prove that Fumadocs rendering, page-tree generation, MDX, and search work before we introduce the repository-wide ingestion adapter.

Fumadocs supports both macro-defined collections and custom static sources, so this separation can be maintained without forcing canonical documents into the website directory. ([Fumadocs][2])

### 3. Final public routes are reserved

| Route             | Purpose                                     | SITE-0001 state |
| ----------------- | ------------------------------------------- | --------------- |
| `/`               | Publication landing page                    | Implemented     |
| `/system`         | Stable reference documentation              | Implemented     |
| `/api/search`     | Documentation search API                    | Implemented     |
| `/building-monad` | Chronological engineering narrative         | Reserved        |
| `/artifacts`      | ADRs, specifications, research, and records | Reserved        |
| `/project`        | Status, roadmap, releases, and build log    | Reserved        |

Only implemented routes appear in the navigation, so the initial application does not expose dead links.

### 4. The repository root remains language-neutral

The script deliberately does **not** create or modify:

```text
/package.json
/bun.lock
/node_modules/
/turbo.json
```

The publication application is independently installable inside:

```text
publication/site/
```

This prevents a TypeScript documentation application from imposing JavaScript workspace semantics on the Monad repository root.

It can later be registered with a root workspace if Monad adopts a formal repository-level workspace mechanism.

### 5. The first content collection uses the Macro API

The initial source is deliberately simple:

```ts
const systemDocs = defineDocs({
  dir: 'content/system',
});

export const systemSource = loader({
  baseUrl: '/system',
  source: systemDocs.toFumadocsSource(),
});
```

This follows Fumadocs’ current Macro API and avoids unnecessary generated `.source` files during the bootstrap stage. Fumadocs documents both the Macro API and the separate Config API; generated type files are primarily relevant when using the latter. ([Fumadocs][3])

## Installation

### Preferred: run the bootstrap script

Download the script and place it at:

```text
tools/bootstrap-monad-docs-site.sh
```

Then run:

```bash
cd /path/to/monad

mkdir -p tools
chmod +x tools/bootstrap-monad-docs-site.sh

./tools/bootstrap-monad-docs-site.sh
```

The script will:

1. Locate the Git repository root.
2. Create `publication/site/`.
3. Write all SITE-0001 files.
4. Install dependencies with Bun.
5. Run the TypeScript type checker.
6. Preserve unknown existing files.
7. Refuse to overwrite an unrecognized existing site unless explicitly instructed.

Start the site:

```bash
cd publication/site
bun run dev
```

Open:

```text
http://localhost:3000
```

The `/system` route should render the initial Fumadocs documentation collection.

Next.js 16 requires Node.js `20.9.0` or newer, which is also declared in the generated `package.json`. ([Next.js][4])

### Alternative: extract the complete scaffold

```bash
cd /path/to/monad
unzip /path/to/monad-docs-site-SITE-0001.zip

cd publication/site
bun install
bun run dev
```

## Script controls

Create files without installing dependencies:

```bash
./tools/bootstrap-monad-docs-site.sh --skip-install
```

Overwrite files owned by the scaffold while preserving unknown files:

```bash
./tools/bootstrap-monad-docs-site.sh --force
```

Create the site at another repository-relative path:

```bash
./tools/bootstrap-monad-docs-site.sh \
  --target tools/publication-site
```
