## What SITE-0002 adds

### Typed application configuration

Site identity, repository links, navigation surfaces, metadata, and feature flags now live in:

```text
publication/site/lib/config/site.ts
```

Environment variables are validated with Zod in:

```text
publication/site/lib/environment.ts
```

Public route definitions and reserved routes are centralized in:

```text
publication/site/lib/routes.ts
```

This prevents route strings, titles, and repository information from being scattered throughout the application.

### Route-group architecture

The application now separates its major presentation modes internally:

```text
app/
├── (publication)/
│   └── page.tsx
│
└── (reference)/
    └── system/
```

The parentheses are organizational route groups, so they do not appear in the public URL.

The result remains:

```text
/          → publication landing page
/system    → reference documentation
```

Future routes are registered but intentionally not linked yet:

```text
/building-monad
/artifacts
/project
```

This makes the intended information architecture explicit without exposing unfinished pages.

### Resilient application states

The scaffold now includes:

```text
app/not-found.tsx
app/error.tsx
app/global-error.tsx
app/loading.tsx
```

These follow the current Next.js App Router conventions for route-level errors, global errors, not-found responses, and loading states. ([Next.js][1])

Shared presentation is implemented through:

```text
components/site/status-page.tsx
```

### Monad identity primitives

Initial reusable brand components now exist:

```text
components/brand/
├── monad-mark.tsx
└── site-identity.tsx
```

They are deliberately restrained at this stage. SITE-0006 will establish the complete visual design system.

## Quality commands

The generated `package.json` provides:

```bash
bun run check
bun run typecheck
bun run test:unit
bun run test:e2e
bun run verify
bun run verify:full
```

The intended distinction is:

```text
verify
├── formatting and static checks
├── TypeScript checking
├── unit tests
└── production build

verify:full
├── everything in verify
└── Playwright browser tests
```

Playwright installation remains an explicit operation because browser binaries should not be downloaded unexpectedly during a normal dependency installation.

## Safe upgrade behavior

The upgrade script:

1. Finds the Git repository root.
2. Confirms the existing SITE-0001 installation.
3. Creates a timestamped backup.
4. Removes only the SITE-0001 route paths that conflict with the new route groups.
5. Applies the cumulative SITE-0002 tree.
6. Installs dependencies unless disabled.
7. Runs the verification suite unless disabled.

Backups are written beneath:

```text
.monad/backups/publication-site/
```

For example:

```text
.monad/backups/publication-site/
└── SITE-0002-20260803T234600.tar.gz
```

Unknown files inside `publication/site/` are preserved.

## Your action required

### 1. Place the upgrade script in the repository

From the Monad repository root:

```bash
mkdir -p tools
```

Move the downloaded script to:

```text
tools/apply-monad-docs-site-SITE-0002.sh
```

Then make it executable:

```bash
chmod +x tools/apply-monad-docs-site-SITE-0002.sh
```

### 2. Apply SITE-0002

Run:

```bash
./tools/apply-monad-docs-site-SITE-0002.sh
```

The script should:

* Back up the current SITE-0001 tree
* Apply SITE-0002
* Run `bun install`
* Run `bun run verify`

### 3. Create your local environment file

```bash
cd publication/site
cp .env.example .env.local
```

SITE-0002 does not require secret values yet, so the defaults can remain unchanged.

### 4. Start the site

```bash
bun run dev
```

Open:

```text
http://localhost:3000
```

Verify:

```text
http://localhost:3000/
http://localhost:3000/system
http://localhost:3000/system/publication-architecture
```

### 5. Install the Playwright browser once

```bash
bun run test:e2e:install
```

Then run the full browser verification:

```bash
bun run verify:full
```
